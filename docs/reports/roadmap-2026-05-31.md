# Roadmap — 3dprint-generator (2026-05-31)

> Gerado por análise multi-agente do código real (7 exploradores + 2 designs de integração + síntese + crítica adversarial). Decisão central: reconectar o Meshy.

## North Star

De "ferramenta interna de logo-em-chaveiro" para **"descreva qualquer coisa → receba um objeto imprimível, muitas vezes articulado, na Bambu H2D"**. O motor paramétrico cobre formas funcionais precisas; o Meshy cobre formas orgânicas/freeform; o flexify transforma isso no diferencial matador: brinquedos articulados print-in-place.

## 🔴 Fazer AGORA (segurança — pré-qualquer-deploy)

- **Rotacionar `AUTH_RESEND_KEY`** — foi colada em chat (nota no `.env`/README) → comprometida.
- **Garantir `E2E_ALLOW_TEST_LOGIN` desligado fora do dev** — é bypass total de auth (está ligado no dev agora).

## ⭐ Prerequisito transversal (elevado pela crítica adversarial)

- **Gate de validade de malha (manifold + parede mínima)** NÃO é item de fase — é pré-requisito que atravessa tudo. Uma malha que não imprime é a pior falha (silenciosa) do produto, e malhas Meshy frequentemente são não-manifold. Implementar junto com a Fase A.
- **Metering de custo + latência + taxa de falha** nas chamadas pagas do Meshy (não só um cost cap), desde o primeiro dia.

## Veredito: Meshy → **RECONECTAR (full)**

**Por quê.** O motor paramétrico é deliberadamente fechado em 3 formas-base (cilindro/placa/disco — "no freeform escape hatch"), então hoje **é impossível** gerar orgânico/complexo (animais, personagens, miniaturas). O `CHORE-003` removeu o Meshy pra entregar um MVP determinístico e de custo zero — decisão de escopo, **não** veredito de qualidade. A remoção foi cirúrgica e **reversível por design**: ficaram intactos a estratégia `generative`, o `meshBlobUrl`, o ciclo `generating→ready` no `/api/generate` e o `repair-mesh.ts` (pós-processador específico de Meshy). **É re-attach, não rebuild (~4-6 dias).**

**Sinal mais forte:** o **flexify** — a feature mais diferenciada — *estruturalmente exige uma malha Meshy como input*. Logo, reconectar o Meshy destrava **duas** capacidades de alto impacto de uma vez.

**Riscos:** custo + latência (pago, assíncrono 30s–min → precisa cost cap + UX de progresso); malhas Meshy frequentemente não-manifold (→ gate de validade antes de fatiar); scope creep (manter paramétrico como default p/ formas funcionais).

## Fases

### Fase A — Destravar freeform (Meshy) · ~4-6 dias
- Re-adicionar `kind:'freeform'` ao `schema.ts` + roteamento no `parse.ts` (LLM decide paramétrico vs freeform). *(baixo)*
- Construir o cliente REST Meshy: text-to-3d + image-to-3d + polling de task (specs TASK-031/040). Reusar `repair-mesh.ts`. *(médio)*
- Plugar freeform no branch generativo do `/api/generate` (infra async já existe). *(baixo)*
- **Gate mínimo de manifold/parede** já nesta fase (crítica: um modelo Meshy que não imprime é pior que nenhum). *(médio)*
- UX de progresso (polling + spinner no chat). *(médio)*
- **Cost cap por usuário/dia** + log de latência/falha/gasto das chamadas pagas. *(baixo-médio)*

### Fase B — Flexify como produto · ~3-5 dias
- `/api/flexify` envolvendo `src/lib/flexify/index.ts`; empacotar o Rocktopus como asset (`public/refs/`). *(médio)*
- Botão "Make it flexi" numa iteração Meshy + preview multi-body (41 corpos) no viewer. *(médio)*
- Tunar/guardar juntas (`jointRadiusFactor`, avisar quando componente usa fallback). *(médio)*
- Headswap como feature secundária. *(baixo)*

### Fase C — Print-readiness · ~3-5 dias
- Wire confiável do serviço OrcaSlicer (`SLICER_URL`/Railway) + health check. *(médio)*
- Gate de validade de malha (manifold + parede mínima) com aviso ao usuário. *(médio)*
- UI de cor/material por corpo pro dual-tool da H2D (A/B). *(médio)*

### Fase D — Polish de produto
- Thumbnails de projeto (captura do canvas na geração). *(baixo)*
- UI de histórico/árvore de versões (schema já tem `parentIterationId`/`currentIterationId`, sem UI). *(médio)*
- Presets/galeria de pontos de partida. *(baixo)*
- Erros de geração visíveis no chat (linhas `status='failed'` existem, mas não aparecem bem). *(baixo)*

## Lacunas operacionais (da crítica adversarial)
- **Sandbox hardening** do JSCAD gerado por LLM segue como backlog em `sandbox.ts` — não esquecer.
- **Estratégia de teste** do caminho Meshy reconectado (E2E com Meshy mockado, à la TASK-036).
- **Backup do volume Postgres** — `projects` + `iterations` são todo o histórico do usuário.

## Riscos globais
- Reconectar Meshy reintroduz exatamente o custo/não-determinismo que o CHORE-003 removeu → disciplina pra manter paramétrico como default.
- Qualidade de junta do flexify só comprovada no polvo Rocktopus; malhas arbitrárias podem articular mal.
- Não-manifold é o modo de falha silencioso que pode tornar as melhores gerações não-imprimíveis.
